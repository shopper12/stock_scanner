# Android 투자판단 품질 리뷰 프롬프트

아래 프롬프트는 Android 투자 앱(Kotlin/Jetpack Compose)의 투자 판단 품질을 점검할 때 사용한다. 목적은 UI 개선이 아니라 실제 매매 판단의 정확도, 재현성, 리스크 통제력을 높이는 것이다.

## 기본 요청문

아래는 내 Android 투자 앱(Kotlin/Jetpack Compose)의 핵심 파일들이다. 코드를 분석해서 투자 판단 품질을 높이기 위해 수정해야 할 항목을 우선순위 순으로 알려줘. 수정은 하지 말고 분석과 지시사항만 알려줘.

## 앱 구조 요약

- `ScannerEngine.kt`: 전체 스캔 로직. Yahoo Finance API 및 가격 시계열 기반 판단.
- `KrShortUniverse.kt`: 한국 단기 후보 종목 목록. 하드코딩 universe 또는 확장 후보군.
- `MainActivity.kt`: UI 및 탭 구성.
- 탭 목록: 요약, 전략, 직접판단, 미국ETF, 환율, 퇴직/IRP, 한국단기, 검증, 기록.

## 붙여넣을 코드

```text
=== ScannerEngine.kt 전체 ===
[여기에 ScannerEngine.kt 내용 붙여넣기]

=== KrShortUniverse.kt 전체 ===
[여기에 KrShortUniverse.kt 내용 붙여넣기]

=== MainActivity.kt 관련 투자판단 UI 부분 ===
[필요하면 한국단기/직접판단/검증/기록 탭 관련 코드 붙여넣기]
```

## 분석 요청 기준

1. 실제 투자 판단 품질에 직접 영향을 주는 버그/한계 위주로 분석한다.
2. 수정 난이도를 `낮음 / 중간 / 높음`으로 표시한다.
3. 각 항목마다 `문제 위치(파일명+함수명)`, `현재 동작`, `문제점`, `수정 방향`, `검증 방법`을 구체적으로 쓴다.
4. 우선순위 1~5위로 정렬한다.
5. 단순 UI 편의성보다 데이터 품질, 신호 품질, 리스크 통제, 검증 가능성을 우선한다.

## 반드시 점검할 핵심 항목

### 1. 데이터 신뢰성

- Yahoo Finance 단일 소스 의존 여부.
- 한국 종목 `.KS/.KQ` 자동 판별 실패 가능성.
- API 실패 시 fallback/mock 데이터가 실전 판단처럼 표시되는지 여부.
- 현재가, 이동평균, 52주 고점, 모멘텀 계산 기준일이 명확히 노출되는지 여부.
- 실시간 가격이 아니라 일봉 종가 기준인데 장중 판단처럼 보이는지 여부.

### 2. 한국 단기매매 universe 품질

- `KrShortUniverse.kt`가 하드코딩 종목에 고착되어 최신 주도 섹터를 놓칠 가능성.
- 거래대금 상위, 거래량 급증, 섹터 회전, 신고가/전고점 돌파 후보를 자동 편입하지 못하는지.
- 같은 섹터 종목이 반복 추천되어 분산 효과가 떨어지는지.
- 2차전지, 반도체, 전력기기, 조선, 방산, 로봇, 바이오 등 주도 섹터 변화에 대응 가능한지.

### 3. 스코어링 품질

- 점수가 단순 12개월 모멘텀과 MA 위치에 과도하게 의존하는지.
- 급등 초입에 중요한 `거래대금 증가율`, `20일/60일 신고가 접근`, `눌림 후 MA20 회복`, `상대강도`, `ATR 대비 손절폭`이 반영되는지.
- 강한 추세주를 고점이라는 이유만으로 배제하거나, 반대로 과열 추격을 허용하는지.
- 쌍봉처럼 보이는 구간을 확정 하락으로 오판하지 않도록 목선 이탈, MA20 기울기, 거래량, 반등 강도를 함께 보는지.

### 4. 리스크 관리

- 진입가, 손절가, 목표가가 같은 기준으로 산출되는지.
- 손절폭이 너무 넓거나 너무 좁은 후보를 필터링하는지.
- 계좌 1% 리스크 기준으로 권장 포지션 크기를 계산하는지.
- 손절가 이탈 후 재해석하지 않는 실패 조건이 표시되는지.
- 목표가가 임의 퍼센트가 아니라 R-multiple 또는 구조적 저항 기준인지.

### 5. 검증과 기록

- 추천 당시의 가격, 기준시각, 데이터 소스, 판단 근거가 기록되는지.
- 이후 수익률, 손절 여부, 목표가 도달 여부를 비교할 수 있는지.
- 전략 수정이 매번 감정적으로 바뀌지 않도록 최소 표본 수와 수정 조건이 있는지.
- mock/live 모드가 기록에 명확히 남는지.

### 즉시 고쳐야 할 것

가장 위험한 버그 또는 실전 판단 왜곡 요소를 1~3개만 적는다.

### 수익률 개선에 가장 큰 것

실제 기대수익 또는 손실 회피에 가장 큰 영향을 줄 개선을 1~3개만 적는다.

### 아직 수정하면 안 되는 것

데이터가 부족하거나 과최적화 위험이 있어 지금 당장 건드리면 안 되는 항목을 적는다.

## 금지사항

- 코드를 직접 수정하지 않는다.
- 일반론만 쓰지 않는다.
- “백테스트 필요”라고만 쓰고 끝내지 않는다.
- UI 디자인 개선을 투자판단 품질 개선보다 앞세우지 않는다.
- 실시간 데이터가 아닌데 실시간이라고 단정하지 않는다.
- mock/fallback 결과를 실제 추천처럼 표현하지 않는다.
